# 远程产物与临时分析

## 1. 总原则

远程端是 GROMACS 运行产物和必要轨迹的长期保留位置；本地工作区是任务元数据、审计、小型结果和交付物的位置。

本地长期区不保留轨迹文件。轨迹包括 `.xtc`、`.trr`、`.dcd`、`.nc` 以及包含连续时间序列的等价归档。既有历史轨迹不自动删除，但新下载不得进入 `tasks/` 或根目录长期区。

本地存在两个存放轨迹的位置，性质不同，不得混用：

| 位置 | 性质 | 是否唯一副本 |
|---|---|---|
| `D:/Temp/GROMACS/<task_id>/<analysis_id>/` | 临时分析缓存 | 否，必须可由远程重建 |
| `Y:/Data/MD_Trajectories/<task_id>/` | 归档保留区 | 通常是，见 §4 |

## 2. 远程保留集合

远程至少保留能支持以下用途的文件：

- checkpoint 续跑和失败诊断；
- 原始日志与阶段状态核验；
- 重新执行 PBC 修正、抽帧和分析；
- 复查最终结构、拓扑、参数和数值门禁；
- 用户已批准的科学结论或下游交付；
- 生成 manifest 和 SHA-256 的来源文件。

通常保留原始生产轨迹、必要的修正轨迹、结构/拓扑、TPR、CPT、EDR 和日志。具体集合由任务 README 和 manifest 冻结，不以“看起来没用”作为删除依据。

## 3. 本地临时目录

所有临时下载、PBC 派生轨迹、抽帧文件、MDA 缓存和中间图像只允许放在：

```text
D:/Temp/GROMACS/<task_id>/<analysis_id>/
```

目录名必须包含任务和分析身份，不使用共享的 `tmp`、桌面或工作区根。分析开始时创建唯一 analysis_id，写入来源和清理策略。

临时目录可以包含：

```text
source/       # 从远程读取的必要样本或短期轨迹
processed/    # PBC、去水、抽帧等派生产物
results/      # 仍需审阅的小型结果
replay/       # 分析命令和参数
```

临时目录不得成为唯一原始证据。结果写回任务根前，确认报告引用了远程源路径、attempt 和哈希。

## 4. 归档保留区（孤儿轨迹）

### 4.1 判定

**孤儿轨迹**指远程端已无从取得的轨迹类数据：计算侧已清理、平台不再提供、或本就只产生于平台侧（如思朗/MaPU 平台的原生 `.trr`、检查点与重启结构）。

判定的唯一依据是**远程实测**，不是推断。迁移前必须逐文件比对远程副本的 `size` 与 SHA-256；比对不通过即视为孤儿。

### 4.2 为什么不能放临时区

`D:/Temp/GROMACS/` 的契约是"可删除、可由远程重建"。把孤儿轨迹放进去，等于让一个按规约可随时删除的位置承载唯一副本——这正是 §3 禁止的"临时目录成为唯一数据来源"。因此孤儿轨迹必须进入性质不同的归档区。

### 4.3 归档规则

```text
Y:/Data/MD_Trajectories/<task_id>/<源相对路径>
```

- **必须保留源相对路径**，不得扁平化；扁平化会丢失来源信息，并在同名文件之间造成静默跳过。
- 归档前逐文件校验 `size` + SHA-256，校验不通过不得删除源。
- 归档区根目录维护 `manifest.csv`，字段：

```text
task_id,relpath,size_bytes,sha256,archive_root,archived_at,status,note
```

- `status` 为 `local-authoritative` 时，声明该数据当前仅此一份。
- 同一清单回写一份到 `tasks/<task_id>/manifests/`。

### 4.4 已知风险

`Y:` 是**网络挂载**（UNC 路径，非本地盘；具体映射以本机 `net use` 为准），可用性依赖 NAS 在线与网络可达。这意味着：

- 断网或 NAS 故障期间，归档数据不可读；
- NAS 自身的冗余与备份策略**未经核实**，不得假定归档区已有第二副本。

网络挂载这一事实不豁免归档前的校验，也不改变 `local-authoritative` 的标注要求。一旦在别处确认了可靠副本，须更新 manifest 状态。

### 4.5 例外与追溯

形成于本规约之前的孤儿轨迹按此规则追溯归档；归档是**移动**而非删除，迁移事实与依据须追加记录到任务 README，不得改写既有执行事实。

## 5. 下载策略

优先在远程完成昂贵或大体积的预处理，并只下载当前分析所需集合。若必须下载完整轨迹，下载到 analysis 临时根，完成后按保留策略清理。

传输可使用临时压缩包，但压缩包不是新的权威产物。解包后逐文件核验远程清单和本地清单；成功后不长期保留重复压缩包。

下载脚本和 `ssh-skill` 的路径转换约束按其 Skill 执行。本文件只规定数据驻留，不复制脚本实现。

## 6. 分析完成门禁

分析完成前必须确认：

1. 源文件、时间范围和抽帧规则记录完整；
2. 轨迹与拓扑原子数、帧数和时间范围匹配；
3. PBC、居中、拟合等操作未覆盖源文件；
4. 小型结果、图表和 manifest 已写回任务逻辑根；
5. 结果状态、限制和未分析范围已记录；
6. 临时文件仍可按 replay 从远程重建。

## 7. 清理

用户未明确授权时，不删除远程轨迹或本地历史目录。允许清理当前分析临时目录中的可重建缓存，但先验证报告和 replay 已固化，并记录清理时间、范围和剩余文件。

`Y:/Data/MD_Trajectories/` 是归档区，**不适用临时目录的清理规则**。其中 `local-authoritative` 的条目在任何副本出现前不得删除；删除归档条目需要用户单独批准并记录依据。

空间治理应采用保留清单、归档清单和清理批准三步。禁止用宽泛通配符清理其他任务。
